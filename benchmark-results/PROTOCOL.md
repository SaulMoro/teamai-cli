# Paired full-suite measurement protocol

- Before: f287dcb1a3fa247206a5dad9766b5d6ef14e3106, verified as Tencent/teamai-cli main when the run started.
- After: local and repeated Actions runs use b7f0bef81fb31fd27aac15c049a5b39227176c4c. The paired Actions run uses 809edbd1090f07b911eedaeb8dafc7e30d41bb40. The second commit changes only CI scheduling and docs; source, package/lock, tsup config, skills and E2E runner are identical between these candidates. Seven-file performance/documentation change only.
- Local: separate real git worktrees and separate npm ci --ignore-scripts installs. Same macOS host, Node v24.21.0, npm 11.19.0, 12 CPUs, 48 GiB RAM. Before and after run sequentially. No other checks for this branch are run during the local pair.
- Actions: https://github.com/SaulMoro/teamai-cli/actions/runs/37667247152. One ubuntu-latest job, sequential before and after, Node 20 set once, separate checkouts and dependency installs. Workflow source is on benchmark/e2e-performance-20261007 at c5e386b7e14425611ad54d5e5174a4fef63562a4, outside the PR branch.
- Both: exact same lockfile, include patterns, assertions, timeouts and credential-free cases. Set retry=0 and cache=false for both variants. No test selection or exclusion flags. Temporary runner HOME, fixture-specific HOME retained, git identity fixed. Remove inherited GIT_CONFIG_GLOBAL so fixture .gitconfig files work. Remote credential variables are removed rather than exposing a maintainer token.
- Measurement boundary: timer includes the build and full E2E command, excludes dependency installation. Before follows existing instructions: npm run build then npm run test:e2e. After uses npm run test:e2e with its new pretest build. This measures the developer verification command and the E2E workload. It does not measure total CI workflow latency or unit-matrix scheduling.
- Workers: before is the committed serial configuration; after is the committed default, four local and two in CI. Default Vitest test isolation remains on. Normal retry=1 stays committed; measurement retry=0 is a diagnostic override.
- Reports: capture full log, Vitest JSON, SHA, Node/npm, OS/CPU, lockfile hash, commands, start/end timestamps, wall seconds, exit code and all case verdicts. Compare each pair by relative filename plus full test name. Aggregate counts alone are insufficient.
- Limitations: one complete pair per environment; baseline runs first. These are observed elapsed times, not medians or a statistical confidence interval. The local host is a developer machine, so unrelated system load may vary; load average is recorded. Both environments omit opt-in credentialed tests. Two previously observed local failures are recorded without modifying their assertions or production code.

The before/after graph change in ci.yml is reviewed separately: prepare-build no longer depends on the lint/unit matrix; E2E needs prepare-build; the existing Build status still needs both preparation and the unit matrix; the fixture concurrency guard remains. No numeric saving for total CI workflow is claimed from the paired test-suite job.
