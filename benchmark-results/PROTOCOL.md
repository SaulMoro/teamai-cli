# Paired full-suite measurement protocol

- Before: f287dcb1a3fa247206a5dad9766b5d6ef14e3106, verified as Tencent/teamai-cli main when the run started.
- After: 47905de7d9d8c865a7c96932cded1b1bdcfabfe5 for every local and Actions measurement (performance change, OpenCode preparation before workers, OpenCode session/cleanup bound).
- Local: separate real git worktrees and separate npm ci --ignore-scripts installs. Same macOS host, Node v24.21.0, npm 11.19.0, 12 CPUs, 48 GiB RAM. Before and after run sequentially, starting only after two minutes with no Vitest worker on the host and a 1-minute load average below 5; load at start and end is recorded.
- Actions: pair https://github.com/SaulMoro/teamai-cli/actions/runs/37682825582, repeat https://github.com/SaulMoro/teamai-cli/actions/runs/37682825678. One ubuntu-latest job per run, sequential before and after, Node 20 set once, separate checkouts and dependency installs. Workflow source is on benchmark/e2e-performance-20261007, outside the PR branch.
- Both: exact same lockfile, include patterns, assertions and credential-free cases. The only timing change is the OpenCode hooks session-creation budget (5 s to 20 s) and its bounded server cleanup. Set retry=0 and cache=false for both variants. No test selection or exclusion flags. Temporary runner HOME, fixture-specific HOME retained, git identity fixed. Remove inherited GIT_CONFIG_GLOBAL so fixture .gitconfig files work. Remote credential variables are removed rather than exposing a maintainer token.
- Measurement boundary: timer includes the build and full E2E command, excludes dependency installation. Before follows existing instructions: npm run build then npm run test:e2e. After uses npm run test:e2e with its new pretest build. This measures the developer verification command and the E2E workload. It does not measure total CI workflow latency or unit-matrix scheduling.
- Workers: before is the committed serial configuration; after is the committed default, four local and two in CI. Default Vitest test isolation remains on. Normal retry=1 stays committed; measurement retry=0 is a diagnostic override.
- Reports: capture full log, Vitest JSON, SHA, Node/npm, OS/CPU, lockfile hash, commands, start/end timestamps, wall seconds, exit code and all case verdicts. Compare each pair by relative filename plus full test name. Aggregate counts alone are insufficient.
- Limitations: one complete pair per environment; baseline runs first. These are observed elapsed times, not medians or a statistical confidence interval. The local host is a developer machine; load average is recorded. Both environments omit opt-in credentialed tests. Pre-existing failures are recorded without modifying their assertions or production code.

The before/after graph change in ci.yml is reviewed separately: prepare-build no longer depends on the lint/unit matrix; E2E needs prepare-build; the existing Build status still needs both preparation and the unit matrix; the fixture concurrency guard remains. No numeric saving for total CI workflow is claimed from the paired test-suite job.
